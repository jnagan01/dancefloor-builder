# Preparation diagnostics
- Keep diagnostics in a separate bounded account-local IndexedDB outbox; serialize owned writes and fence reads/acknowledgements by session and revision, because logging must never touch event or music persistence.
- Merge owned session memory into successful reads by stable ID/revision and same-revision delivery progress around runs begun during activation (keep their live row identity; interrupt only restored runs); synchronize bounded memory on pruning and retain an owner pruning watermark, because quota failures can leave stale readable records and a pending read must not interrupt a live generation.
- Rebuild remote/copy payloads from the shared allowlist; only the authenticated handler reads ingestion secrets, because raw provider errors and identifiers must never leave the device.
- Diagnostic work is best-effort and independent of generation; transport deadlines/backoff never alter preparation budgets or recommendations.
- Keep candidate exclusion high-water counts informational and separate from final selected-addition drops; fence context fallback notices by request settlement and generation/account identity, because retries/late replies must not duplicate or misattribute outcomes.
- Snapshot the shared sidebar installed-version resolution synchronously at run start; label web/desktop separately and keep the exact allowlisted build ID, because IPC and late identity replies must never delay or rewrite a run.
- Synthetic connection checks use the same validated relay with an explicit empty-success marker and informational level, because connection verification must not resemble a real preparation failure.
- Map real run statuses to fixed relay levels (failed=error; warnings/short/interrupted=warning; other statuses=info); synthetic checks always stay info, because client severity must never control transport classification.
- Copy user-visible text via `src/lib/copyText` (gesture-time selection copy inside the dialog first, async Clipboard API second, visible text fallback on failure), because the installed desktop permission policy denies the async Clipboard API.
- Derive service wording from fixed cause categories and aggregate metadata warnings at final coverage; running/missing/short totals cannot claim completion, because a parked phase is not an actual request timeout.
