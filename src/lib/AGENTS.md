# Online metadata scheduling
- Use small serial generation chunks, independent bounded provider lanes and rate-paced grouped recording searches; retain partial streamed estimates and stale-generation fences, because queue volume or one hung provider must not monopolize lookup time.
- Keep the cache adapter service-only behind authenticated handlers and existing schema; isolate timing/cache fixtures from real providers, accounts and files.
- Wait for dynamic provider cooldowns in the gatherer's fenced pre-dispatch scheduler, not inside timed RPC callbacks; mark attempts and spend budget only when sending, because a late wait must never launch abandoned work.
- Reuse unused phase time inside the fixed request end for estimates, preserve streamed partials on failure, and reserve observed dispatch latency before the generation cutoff; no deadline extension or transient negative cache.
- Bound recommendation prompt context separately from complete local credit/version exclusion; run one in-flight suggestion lane per deficient section with client deadlines above the client-requested server deadline and server-side partial retention; validation stops all lanes, timeouts stay lane-local, because a bounded wire sample is not the dedupe universe and one slow section must not starve or orphan others.
- Run one acoustic-estimate lane: an evidence-first group from completed gaps, then at most one speculative group for every remaining gap (also forced at the final dispatch reserve), with a non-reasoning model chosen by measured first-delta latency inside the window; estimates only fill gaps, body reads stay inside request deadlines and cooldowns are rechecked after waking within six lanes, because serial or reasoning-model start-ups miss the fixed 16s end.
- Count bounded per-provider causes (numbers only) and treat catalogue 404 as a definitive miss; refine truncated grouped recording searches with paced single-song searches only while the shared lane is open; size suggestion requests from prior/measured pace within part of the window, because unlabelled failures and deadline-edge requests hide root causes.
- Give the client-request and expansion lookup phases separate bounded windows on the shared gatherer and memoize exact-pair library matches per generation, because local preparation on large indexes must not consume lookup time.
- Dispatch optional context lazily behind its deadline and event/account fence, bound advisory completion metadata by the request deadline, and recount shared favorite admission after parallel replies, because abandoned work and stale counts must not escape lifecycle bounds.
- Stage expansion as section lanes beside one deficit-prioritized worker; admit finite 90s continuations only after useful verified yield within an eight-minute hard ceiling and the shared 600 candidate budget, retain single-call caps/fences, and reopen sourcing after invalidated coverage, because phase expiry is not source exhaustion.
- Unregister single-use coordinator waits and yield a timer turn after bounded same-timestamp iterations; explicit user decade/BPM limits override prompt section defaults, because microtask-only wake cycles and conflicting era advice undermine bounded useful progress.
