# Track information reuse

Public parsed evidence is separate from events, selections, prep knowledge, indexes and audio. The additive `track_evidence_cache` is RLS-enabled and service-only; existing metadata rows/grants are not changed. Authenticated handlers dynamically load its adapter. Missing schema and storage failures preserve available results and report bounded failures.

Keys retain literal full artist credit and recording/version titles plus provider/result shape. There is intentionally no primary-only, basename or fuzzy cache alias. Canonical Last.fm similarity uses autocorrect off and a bounded 30-row result; consumers slice only after the shared result. Exact community responses are identity-validated before reuse. Details search candidates remain advisory and cannot approve files.

Freshness: stable provider facts/positive recording searches 365 days; definitive empty recording searches 24 hours; AI/heuristic local acoustic facts 30 days; required popularity 7 days; community/details 24 hours; similarity/artist audience 6 hours. Successful dated stale context can serve as fallback for up to 365 days on refresh error. Legacy metadata rows retain known stable facts beyond the old 90-day cutoff and keep conservative provenance. Per-field dates are stored in separate evidence, not by rewriting old rows. Unchanged fields retain value-change dates but successful verification renews their independent checked dates. Popularity-only refresh uses search without audio-features when acoustic evidence is trustworthy and fresh. Local reuse and server refresh share one field decision (`fieldDue`/`advisoryStale`): any needed known field stale by its last check makes a local hit ineligible, exactly when the server would refresh it. A settled, non-failed provider answer without a stronger value records a per-field `missed` date (24-hour cooldown) but never renews the value's check or change date; transient 429/5xx/network/timeout outcomes record nothing. Stale AI-or-weaker values get one bounded re-estimate after providers settle; a successful estimate renews only its check date (value-change date moves only when the value/provenance changes). The local IndexedDB write applies the trigger's per-field provenance/date merge in its own readwrite transaction. Generation caps the shared canonical 30-row similarity at its original 20 per seed (details 15). Atomic SQL merging scales the authoritative `provenance.ts` ordering by two (user12/measured10/tags8/VirtualDJ8/provider6/catalogue4/AI3/estimate2/filename2/unknown0). No polling or background list mutation.

Local IndexedDB `setarchitect-track-information-v1` is account-scoped, capped at 3000 entries per owner and 64 KiB per entry. It is not included in event/library/offline backups. Storage operations have bounded waits; corruption is ignored, not rewritten. Consumer fences discard stale account/subject/generation replies. Shared unresolved work retains its slot until actual settlement; independent consumer deadlines never spawn duplicate producers or cancel another consumer. Enrichment's existing gatherer remains the owner of its 20s transport cutoff and recovery gate.

Counts distinguish local/database reuse from actual external fetch dispatches (enrichment counts outbound HTTP calls, not server RPCs). Storage writes count only after confirmation. Diagnostic reuse counts use an optional allowlisted numeric field, leaving the original notice enum unchanged. Unchanged schema-1 readers accept the run and strip that optional field. No new telemetry destination.
