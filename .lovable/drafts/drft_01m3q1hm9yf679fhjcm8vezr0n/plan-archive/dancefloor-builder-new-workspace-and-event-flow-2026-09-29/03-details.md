## Pages and workflow

1. **Home:** indexed track/artist counts, source health, recent events, and rankings. Use available DJ-software play counts for Most played; label saved-event appearances as a **request proxy**, not confirmed requests, and recent event appearances as Trending in your events. Show unavailable states where the selected DJ software exposes no play history.
2. **Events:** searchable previous events and New event. New-event order: dance-floor details → CSV/TXT upload or optional Spotify link → edit/add/remove imported songs and review duplicates → expansion on/off with a 2×/3×/4× buffer → Warm Up, Transition, and Peak one at a time. A public Spotify playlist link can be tried without account setup; if anonymous access fails, explain it and offer CSV/TXT instead. Private playlists are not promised.
3. **Library:** only user-selected audio folders feed local search and matching—remove VirtualDJ database upload. Search, sort, play, edit in-app metadata, add/remove sources, and rescan. Show file paths when supplied by the picker, not fabricated absolute paths. Persist the index on this device for the signed-in user; prompt to reconnect inaccessible folders. Do not silently rewrite embedded audio tags.
4. **Settings:** initial number of match results (default 10), optional bulk track matcher actions, selected DJ software (VirtualDJ, Serato, Rekordbox, Other), export destination, existing profile preferences, password change, and sign out. VirtualDJ keeps direct export; other software gets a labeled compatible M3U rather than an unverified native integration. Real play counts appear only when imported DJ data supplies them.
5. **List review:** export controls at top, then summaries and All / Matched / Unmatched / Review needed filters for **only the active list**. Metrics beside each searched song; inline local results below it with left-hand confidence, real file path, known play count, key, BPM, playback and multi-select checkboxes. Browsing a local file adds it checked. Configurable initial results still allow full-library search. Matcher toggle and Select first / Most played / All / None act on the current list; disable Most played when counts are unavailable. Results and page scroll together. Offer direct configured VirtualDJ export plus M3U/PDF/CSV downloads and portable M3U to the selected folder for other software.
6. **Playback and updates:** playing a connected local audio file opens a compact waveform strip along the bottom, not a centered dialog. Show version in the navigation and on Check for updates. Compare running web build with the latest published web build, offer refresh when newer, and clearly separate web refresh from native desktop installer updates; only claim an installer is current when verified from a reliable release source.
7. **Autosave:** create one event when lists generate; update that same event after subsequent edits, match selections, and event changes. Show saving/saved/error with retry, preserve manual selections on reopening, and avoid stale writes into another event. Remove manual Save to history. Blank/partial song rows do not block saving.

## Technical approach

- Split the single authenticated builder page into an authenticated workspace shell and distinct Home, Events, Library, Settings, and Updates routes with page-specific metadata. Reuse the auth gate, profile, saved library index, matching engine, history table, and export helpers.
- Use the existing owner-scoped event record with an update operation and a backwards-compatible JSON snapshot for matches and buffer. Keep older saved events readable. Scope local library storage by account to prevent cross-user leakage. Pass the selected buffer into the existing target calculation without changing recommendation or placement algorithms.
- Regression-test generation, match choices and filters, local-folder-only results, folder permissions, autosave isolation, legacy events, exports, and desktop/mobile layouts.

**Limits:** Spotify public-link import and DJ-software play counts depend on external access or files the user provides; absent data will be identified, never invented. Local audio and permissions remain on the DJ’s device. This draft shares a live backend; avoid bulk changes. Any new database structure would be staged to apply when the draft is accepted, not run now.
