# Desktop architecture
- Keep the pre-rebrand bundle ID and pinned Dancefloor Builder userData path in main.cjs, because changing them loses tag cache, backups, folder permissions and update continuity.
- Apply security.cjs to every native IPC handler and navigation/permission boundary; trust only the exact app origin and owning main frame, because untrusted pages/subframes must never inherit native access. Include desktop helpers in package build.files.
- Keep electron-updater autoDownload and autoInstallOnAppQuit disabled; invoke Squirrel only after a fresh backup and fsynced draft with editing frozen, because Mac staging can install on ordinary quit.
- Stamp real app semver and release tags from the single release workflow run counter; verify ZIP/DMG/feed checksums and Developer ID/notarization before release, because cached updates and legacy bootstrap must identify the same increasing version.
- Keep the provided icon source as RGBA and validate source, ICNS roundtrip and packaged ZIP/DMG icons before release, because resizing or packaging must never flatten transparent corners.
- Verify Developer ID using captured codesign display verbosity 4 and stapled tickets on the inner app in both ZIP and read-only mounted DMG; never require a ticket on an unsubmitted wrapper or mutate checksum-covered artifacts.- Serve the offline workspace only from bundled desktop/offline assets via the private scheme in its own in-memory session, CSP and offline-preload; its IPC accepts only that window's main frame, because the web-origin bridge must never gain file or cross-account access.
- Make offline copies readable only through the active-account marker committed by a serialized, generation-fenced prepare; revoke synchronously on sign-out/account change, closing the offline window and denying in-flight replies, and keep offline choices in account+event+snapshot-version overlays, because stale async work must never re-expose or alter account data.
- Gate offline availability on an in-memory revoked flag plus a durable fsynced revocation epoch carried by the active marker; revoke synchronously outside the prepare queue and require a fresh accountSeen before prepare, because queued unlinks and crashes must never resurrect a revoked account.
- Keep offline eligibility separate from the writer's completed track count; failures, cancellation and rollback leftovers count as zero exported, because a planned playlist is not a successful write.
- Read and write song metadata tags only inside the Mac app (desktop/tags.cjs via node-taglib-sharp, cached by size+mtime in userData), because browsers cannot modify local files and edits must land in the music files themselves.
- Mirror native event recovery in an fsynced, account/event-key-hashed journal behind exact-origin main-frame IPC; keep existing browser recovery keys, because Chromium localStorage alone did not survive an abrupt process kill.
- Install desktop deps in CI with npm ci from package-lock (Bun ignores nested overrides), then run electron/install.js and verify-install.cjs; keep bun.lock regenerated only by the workflow-pinned Bun, because Electron 43 has no postinstall and the patched helpers must be what consumers load.
